# 农产品价格监测预测分析平台

面向农业主管部门、批发市场、合作社与金融机构的价格监测、短期预测、预警处置与决策支持平台。系统围绕「采集—治理—监测—预测—预警—决策支持」闭环，提供驾驶舱、价格监测分析、短期与批量预测、模型管理与漂移监测、预警规则与处置、情景推演、分析报告、数据治理、后台管理、开放 API 与数据大屏十二个业务模块，并配套站内通知中心。

- 前端：Vue 3 + TypeScript + Vite + Element Plus + ECharts + Pinia
- 后端：FastAPI + SQLAlchemy + MySQL 8.0 + Redis 7 + MinIO（S3 对象存储）+ pandas / NumPy / scikit-learn / statsmodels
- 部署形态：单机 B/S，前后端分离，生产构建由后端统一托管静态资源
- 数据服务：MySQL 承担业务数据存储（可切回内置 SQLite 文件库），Redis 承担热点缓存、限流与令牌注销黑名单，MinIO 承担报告/模型产物/导入文件的对象存储，Mailpit 承担本地收件箱验证；四者均支持不可用时降级
- 鉴权：HS256 JWT + PBKDF2 口令散列 + RBAC 权限点（21 个权限点、4 个内置角色）；开放 API 另支持调用方密钥 `X-Api-Key` 与按调用方限流（超限 429 / `E4290`）
- 增强能力：模型漂移监控（PSI）、批量预测后台异步执行、站内通知中心与处置 SLA、报告 Excel 导出、开放 API 调用统计、全屏数据大屏
- 基础设施能力：定时任务调度与运行史（cron 五段解析、失败重试）、对象存储、结构化日志与接口指标、邮件通道、模型实验跟踪、一键备份

## 业务流程与界面

平台按「采集—治理—监测—预测—预警—决策支持」闭环组织，业务人员从数据接入开始，经监测分析与预测预警，最终形成报告与调度决策：

```
数据接入 → 数据治理 → 价格监测 → 价格预测 → 预警处置 → 情景推演 → 分析报告 → 决策支持
```

| 环节 | 业务动作 | 界面入口 | 主要产出 |
| --- | --- | --- | --- |
| 1 数据接入 | 登记数据源、上传价格明细 | 数据治理 → 数据源管理 / 数据导入 | 价格记录入库、导入任务与错误明细 |
| 2 数据治理 | 查看完整率、重复率、异常与缺失，处置问题记录 | 数据治理 → 数据质量 | 质量指标、异常明细与处置状态 |
| 3 价格监测 | 按品种/地区/市场类型筛选，查看走势、同比环比、季节指数、区域价差与品种比价 | 总览 → 综合驾驶舱；价格监测 → 价格监测 / 监测分析 | 价格走势与监测口径指标 |
| 4 价格预测 | 选择品种与地区生成短期预测；对多品种多地区发起批量预测；查看模型精度与漂移 | 预测分析 → 短期预测 / 批量预测 / 模型管理 / 模型监测 | 预测点、置信区间、方向、因素贡献 |
| 5 预警处置 | 查看预警、确认与关闭并记录处置结论；维护预警规则 | 预警管理 → 预警信息 / 预警规则 | 分级预警、处置记录与处置时效 |
| 6 情景推演 | 设置产量、运费、政策、替代品与气象冲击，推演价格变化与风险区间 | 情景推演 | 价格变动幅度、区间、因素贡献与建议 |
| 7 分析报告 | 生成日报/周报/月报，导出 HTML / Markdown / Excel | 报告中心 | 报告正文、指标摘要与导出文件 |
| 8 决策支持与运营 | 数据大屏值守、站内通知、任务调度、用户与权限、审计与系统监控 | 数据大屏 / 通知铃铛 / 后台管理 | 值守视图、运行记录与审计留痕 |

### 流程一：数据接入与治理

1. 进入「数据治理 → 数据源管理」，确认各接入通道状态与最近同步时间，必要时点击「同步」刷新；
2. 进入「数据治理 → 数据导入」，先下载导入模板，按模板填写品种、地区、市场类型、日期、价格、成交量与价格区间后上传；
3. 进入「数据治理 → 数据质量」，查看完整率、重复率、异常与缺失记录，对问题记录执行「处置」并填写处理结论。

### 流程二：价格监测与分析

1. 登录后进入「综合驾驶舱」，查看品种/区域/市场规模、平均价格、未处置预警与最新预测，切换品种与地区查看近 90 天走势；
2. 进入「价格监测 → 价格监测」，按品种、地区、市场类型与日期筛选，切换日/周/月粒度查看走势与明细，需要留档时点击「导出 CSV」；
3. 进入「价格监测 → 监测分析」，查看区域价差、品种比价指数（首日=100）与季节指数，判断价格是否偏离常态。

### 流程三：价格预测

1. 进入「预测分析 → 短期预测」，选择品种、地区与预测天数（7/14/30 天或自定义），点击「开始预测」；
2. 阅读结论卡（预计变动幅度、趋势、风险与置信度），在走势图中查看预测区间，在明细表中核对逐日预测点，在「因素贡献」中了解主导因素；
3. 需要覆盖多品种多地区时，进入「批量预测」多选品种与地区后提交，页面自动轮询进度，完成后可导出 CSV；
4. 进入「模型管理」查看在用模型与回测表现，进入「模型监测」查看 PSI 漂移等级，对漂移模型执行「重训」。

### 流程四：预警与处置

1. 进入「预警管理 → 预警信息」，按等级、状态、品种与地区筛选，点击「统计」区了解未处置数量与处置率；
2. 打开预警详情，点击「处置」填写处置说明，关闭时补充处置结果，预警状态变为「处理中」或「已关闭」；
3. 进入「预警管理 → 预警规则」，维护价格阈值、波动率、同比与跨区价差规则，设置等级、窗口天数与通知渠道，可启停规则；
4. 顶栏通知铃铛会收到扫描、确认、关闭、导入、训练、报告与调度任务产生的站内通知。

2. 查看预测价格变动、价格区间、走势对比、主要影响因素与决策建议，历史推演可在列表回看；
3. 进入「报告中心」，选择报告类型与统计周期生成报告，可在列表下载 HTML、Markdown 或 Excel 版本。

## 快速开始

```bash
# 1) 启动并检查数据服务（MySQL 13306 / Redis 16379 / MinIO 9000-9001 / Mailpit 1025-8025；复用本机已有容器，缺失时提示用 compose 拉起）
npm run infra:up

# 2) 安装依赖
python -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements.txt
npm install
npm install --prefix frontend

# 3) 构建前端并生成种子数据（首次建库会自动创建 3 年日频价格数据与 30 个在用模型）
npm run seed

# 4) 开发模式（后端 8017 + 前端 5177 同时启动）
npm run dev

# 5) 生产构建与整体验收
npm run build
npm run gate
```

`npm run seed` 会重建 MySQL 库 `agri_price` 中的业务数据（清空后重新导入）：5 个品种 × 6 个地区 × 12 个市场 × 2023-01-01～2026-11-11 日频价格与特征、预警规则与预警记录、分析报告、数据源、导入任务、质量异常、调度任务与审计日志，并训练季节分解、Holt-Winters、梯度提升回归和回测加权组合模型，输出示例预测结果。种子使用固定随机种子，可重复重放；`npm run seed -- --no-models` 可跳过模型训练快速建库。

## 常用命令

| 命令 | 作用 |
| --- | --- |
| `npm run infra:up` | 检查并启动 MySQL/Redis/MinIO/Mailpit，幂等准备业务库、账号、桶与连通性 |
| `npm run backup` | 导出 MySQL 结构与数据、关键表行数与对象清单到 `.runtime/backups/`，保留最近 7 份 |
| `npm run infra:down` | 停止由 `deploy/docker-compose.yml` 启动的数据服务 |
| `npm run dev` | 同时启动后端 8017 与前端 5177 |
| `npm run build` | 前端类型检查 + 生产构建，产物输出到 `frontend/dist` |
| `npm run seed` | 重建种子数据库（`--reset` 清空业务数据） |
| `npm run perf:batch` | 批量预测吞吐压测（默认 30 组合 × 14 天，输出每秒点数与 1 万点外推） |
| `npm run test:api` | 启动后端并执行接口契约与权限隔离断言 |
| `npm run test:e2e` | 使用 Playwright 执行端到端用例（需先 `npm run build`） |
| `npm run db:validate` | 校验数据库表结构、数据规模、引用完整性与取值合法性 |
| `npm run check:docs` | 校验交付文档、截图与页面完整性 |
| `npm run screenshots` | 生成 `docs/screenshots` 全套页面截图 |
| `npm run gate` | 依次执行构建、数据库、接口、端到端、文档五道门禁 |

每道门禁最后一行固定输出：

```
RESULT=PASS passed=N failed=M 用时=Ss
```

`npm run gate` 汇总五道门禁结果，任一失败即视为交付不合格。

## 接口约定

- 统一响应：`{"code": "0", "message": "ok", "data": ...}`；分页数据为 `{"list": [], "total": 0, "page": 1, "page_size": 20}`
- 错误码：`E4001` 参数校验失败、`E4002` 参数格式错误、`E4010` 未认证/凭证失效、`E4030` 无权限、`E4040` 资源不存在、`E4090` 状态冲突、`E4290` 调用频率超限、`E5000` 服务内部错误
- 鉴权：除 `POST /api/auth/login` 与 `GET /api/health` 外均需 `Authorization: Bearer <token>`
- 完整端点表、字段说明与角色权限映射见 `docs/接口契约.md`
- 开放 API 位于 `/api/open/v1/*`，供第三方系统读取价格、预测、预警、报告与运行指标；鉴权支持平台 token 或调用方密钥 `X-Api-Key`，按调用方每分钟限流，调用流水保留 7 天并可在页面查看用量
- 缓存：驾驶舱、字典、价格序列与模型性能接口命中缓存时返回 `X-Cache: HIT`；导入、同步、预警扫描后自动失效
- 增量契约（M2 新增接口与字段）见 `docs/接口契约-M2.md`

## 数据与指标口径

- 价格单位统一为「元/公斤」，日期粒度日频
- 短期预测 MAPE 目标 ≤ 15%，方向准确率目标 ≥ 65%（主口径为 30 日趋势累计方向命中率；接口同时返回 7 日/单日参考口径与说明字段）
- 驾驶舱与监测页的同比、环比、季节指数、区域价差、品种比价指数均以数据库实时聚合，不使用硬编码常量
- 模型漂移以 PSI 衡量：比较最近 90 天与之前 180 天的日收益率分布，`<0.1` 平稳、`0.1~0.25` 关注、`>0.25` 漂移
- 批量预测为后台异步执行，进度写回任务记录；压测口径见 `npm run perf:batch`
- 种子数据由固定随机种子生成，重建后指标可复现，便于对照验收

## 常见问题

1. **构建时报 `esbuild ... Access is denied`**：本机系统临时目录清理受限，`npm run build` 已自动将 `TMP/TEMP` 指向 `frontend/.tmp`；手工执行时同样建议设置该环境变量。
2. **控制台中文乱码**：Windows 控制台默认 GBK，执行脚本时设置 `PYTHONIOENCODING=utf-8`（门禁脚本已内置）。
3. **数据服务未就绪**：执行 `npm run infra:up`；若提示容器不存在，用 `docker compose -f deploy/docker-compose.yml up -d` 启动并等待健康检查通过。MinIO 镜像在部分网络下无法拉取，脚本会自动使用官方社区版服务端二进制，无需额外操作。
4. **MySQL 连接被拒或库为空**：确认容器映射端口为 13306、库名为 `agri_price`；`npm run seed` 后可用 `npm run db:validate` 校验数据规模。
5. **Redis 不可用**：接口会自动降级为直连数据库（健康检查 `cache` 字段显示 `error`），页面功能不受影响；恢复 Redis 后缓存自动重新填充。
6. **数据库被占用**：停止占用 8017 端口的进程后重试 `npm run seed`；`.runtime/` 下的日志与导入产物可安全删除。
7. **首次启动较慢**：首次种子需要训练 30 个模型（约 2 分钟），之后启动直接读取已有数据。
8. **开放 API 返回 429 / `E4290`**：触发调用方每分钟限流，按响应头 `Retry-After` 重试或调高该调用方限流值。
9. **通知铃铛无未读数**：当前账号没有未读通知；处置一条预警或导入一次数据后即可看到新通知。
