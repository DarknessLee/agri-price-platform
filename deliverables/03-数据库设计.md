## 1 概述

### 1.1 目的与范围

本文档描述系统正式库 `agri_price` 的物理设计与逻辑设计，覆盖系统权限、主数据、价格与特征、模型与预测、预警、情景与报告、数据治理与审计、增强能力、基础设施共 9 组 30 张表。文档只描述结构与口径，不重复逐字段字典；字段级中文说明见 `docs/数据字典.md`。

### 1.2 设计原则

1. 单一数据库承载全部业务：主数据与事实数据同库，避免跨库事务；价格事实表按月增长，其余表体量小。
2. 主数据使用编码而非硬编码：品种、地区、市场、数据源均落表，业务表通过整型主键或编码外键关联。
3. 事实表只追加不修改：价格、特征、预测、审计、调用流水等以插入为主，质量问题与预警状态允许更新并保留处置人、处置时间。
4. 数值口径统一：价格与金额单位为元/公斤，保留 2 位小数入库；百分比字段按百分数数值存储（4.22 表示 4.22%）。
5. JSON 语义字段以 TEXT 存储：模型参数、预测解释、情景冲击、报告指标等采用 JSON 字符串，由应用层序列化，便于不同数据库方言移植。

### 1.3 术语

- 序列：品种 × 地区 × 市场类型的一组按日价格数据。
- 组合：品种 × 地区的一组模型与预测对象。
- 基线窗口：漂移计算中作为参照的历史时间窗。
- 种子数据：由 `npm run seed` 一次性生成的验收基线数据，可重复重建。

## 4 ER 关系说明

### 4.1 主数据到事实表

- `dim_variety` 1 → N `price_record`（variety_id）
- `dim_region` 1 → N `price_record`（region_id），`dim_region` 1 → N `dim_market`（region_code）
- `dim_market` 1 → N `price_record`（market_id）
- `dim_data_source` 1 → N `price_record`（source_id），1 → N `import_task`（source_id）
- `dim_variety`、`dim_region` 1 → N `feature_record`
- 事实唯一粒度：品种 × 市场 × 日期 × 市场类型，由 `uq_price_point` 保证同一序列同日不重复。

### 4.2 模型到预测与实验

- `model_version` 1 → N `forecast_result`（model_id）
- `model_version` 1 → N `backtest_record`（model_id）
- `model_version` 1 → N `model_run`（model_id），每次训练写一条实验记录
- `forecast_batch` 1 → N `forecast_batch_item`（batch_id），批次汇总数量与进度，明细逐组合记录
- 同一品种 × 地区允许存在多个模型版本，`is_active`/`status` 标记在线版本，数据库不强制唯一，由应用层保证单一在线。

### 4.3 预警规则到预警记录

- `alert_rule` 1 → N `alert_record`（rule_id）
- 预警记录同时冗余品种与地区，便于按区域、品种直接筛选，避免多表连接
- 规则命中计数 `hit_count` 随扫描累加；预警处置状态与处置人、处置时间保留在同一行

### 4.4 治理与报告

- `price_record` 1 → N `quality_issue`（price_id），质量问题可追溯到具体价格行
- `import_task` 记录一次导入的成功与失败行数，失败明细以 JSON 存 `errors`
- `report` 以 `variety_ids`、`region_ids` 记录筛选范围，正文摘要与指标以 TEXT 存放
- 报告、导入原件与模型产物均登记对象键，文件本体存对象存储，库内只存路径或对象键

### 4.5 通知与开放 API

- `open_api_client` 1 → N `open_api_call`（client_id），流水按天统计调用量与耗时
- `sys_notification` 以 user_id 归属用户，user_id=0 表示全员可见；预警、导入、报告、任务事件均写入通知
- `sys_email_log` 独立记录邮件通道投递结果，与通知表互不依赖，失败原因单独留痕

### 4.6 调度与审计

- `scheduled_task` 1 → N `scheduled_task_run`（task_id），运行史保留任务键与任务名快照
- 审计日志不设外键级联，避免用户删除后历史记录丢失；记录 user_id 与 username 双份
- 所有写操作（导入、增删改、处置、训练、启停、任务执行）统一写 `audit_log`

## 7 存储与保留策略

### 7.1 存储参数

- 全部表使用 InnoDB 与 utf8mb4，单表数据量最大为价格表 84,660 行，低于千万级，无需分表分区。
- 价格与特征数据按日期连续追加，历史数据不删除；导入去重依赖 `uq_price_point`，重复行跳过并计入任务统计。
- JSON 语义字段（`params`、`explain`、`errors`、`metrics`、`shock`、`chart`）以 TEXT 存储，长度上限由应用层校验。

### 7.2 保留与清理

| 数据类别 | 表 | 保留策略 | 清理方式 |
| --- | --- | --- | --- |
| 调度运行史 | `scheduled_task_run` | 保留最近 30 天 | 任务执行时按时间条件删除过期行 |
| 开放 API 调用流水 | `open_api_call` | 保留最近 7 天 | 写入调用流水时顺带删除过期行 |
| 站内通知 | `sys_notification` | 保留最近 90 天 | 通知写入时按时间条件清理 |
| 邮件发送记录 | `sys_email_log` | 随备份轮转保留 | 由备份与巡检策略控制，不单独清理 |
| 审计日志 | `audit_log` | 长期保留 | 满足合规追溯要求，不自动清理 |
| 业务事实数据（价格、特征、预测、报告） | `price_record` 等 | 长期保留 | 仅随重建种子数据整体复位 |

### 7.3 自增复位与重建

- 重建命令：在仓库根目录执行 `npm run seed`（MySQL 正式库，约 126 秒，含 120 个模型训练）；开发环境执行 `python -m app.seed --reset`（SQLite，`.runtime/agri.db`）。
- 复位语义：`--reset` 删除并重建全部 30 张表，自增主键从 1 开始，随后按种子基线重新写入 84,660 条价格、31,380 条特征及各表基线数据。
- 增量补齐：不带 `--reset` 时仅补齐缺失表数据，已存在的数据不重复写入。
- 备份：`scripts/backup.mjs` 导出数据库与对象存储，保留 7 份，恢复流程见《部署运维手册》。

## 8 常用查询与容量估算

### 8.1 典型查询

1. 价格序列（按日聚合，命中 `ix_price_series`）：

```sql
SELECT price_date, AVG(price) AS price
FROM price_record
WHERE variety_id = 1 AND region_id = 1 AND market_type = '批发'
  AND price_date BETWEEN '2023-01-01' AND '2026-11-11'
GROUP BY price_date
ORDER BY price_date;
```

2. 最新价格日与当日均价（驾驶舱总览）：

```sql
SELECT MAX(price_date) FROM price_record;
SELECT AVG(price) FROM price_record WHERE price_date = '2026-11-11';
```

3. 最新特征快照（用于同比、波动率回填）：

```sql
SELECT yoy_pct, mom_pct, volatility_30d, seasonal_index
FROM feature_record
WHERE variety_id = 1 AND region_id = 1
ORDER BY calc_date DESC
LIMIT 1;
```

4. 季节指数月度均值（命中 `ix_feature_series`）：

```sql
SELECT MONTH(calc_date) AS month, AVG(seasonal_index) AS idx
FROM feature_record
WHERE variety_id = 1
GROUP BY MONTH(calc_date)
ORDER BY month;
```

### 8.2 容量估算

| 表 | 行数（种子） | 单行估算 | 数据量估算 | 说明 |
| --- | --- | --- | --- | --- |
| `price_record` | 84,660 | 约 150 B（含索引） | 约 13 MB | 60 序列 × 1,411 天 |
| `feature_record` | 31,380 | 约 110 B（含索引） | 约 3.5 MB | 2024-01-01 起逐日 |
| 其余 28 张表 | 合计约 760 行 | 约 300 B | 约 1 MB | 配置、模型、预警、报告、通知等 |
| 全库（含索引与日志） | — | — | 约 20 MB，预留后可控制在 100 MB 内 | 备份 7 份约 140 MB |

- 日增数据量：价格约 60 行/日、特征约 30 行/日，年增量约 3.3 万行，十年内仍为百万级，单一 MySQL 实例足够承载。
- 驾驶舱聚合查询依赖最新日期过滤与索引覆盖，实测 40～90 ms；缓存命中时低于 10 ms，详见《测试报告》。
