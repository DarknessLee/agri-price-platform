# 农产品价格监测预测分析平台 系统设计说明书

文档版本 V1.0 ｜ 编制日期 2026-11-13 ｜ 对应交付物：开发书 §12 第 2 项
适用读者：架构评审、开发与运维人员

## 1. 设计目标与约束

| 项目 | 说明 |
| --- | --- |
| 设计目标 | 单机可部署的 B/S 系统，覆盖采集治理、监测分析、预测预警、情景与报告全链路，指标可复核 |
| 部署约束 | 单位内网单机（Windows/Linux 均可），不使用云服务，不依赖外部网络 |
| 规模约束 | 价格数据 8～10 万行、并发用户 ≤50、日请求量 ≤2 万，MySQL 单实例足够 |
| 资源约束 | 内存 16GB、磁盘 260GB 可用；镜像拉取受限时允许降级为本地二进制/文件存储 |
| 交付约束 | 一键重建种子数据、五道门禁可重复执行、文档与实现一致 |

## 2. 总体架构

系统采用前后端分离的三层架构，基础设施层由数据库、缓存、对象存储、邮件与调度器组成。

```
┌────────────────────────── 表现层（Vue 3 + Element Plus + ECharts）──────────────────────────┐
│ 驾驶舱 │ 价格监测 │ 监测分析 │ 短期/批量预测 │ 模型管理与漂移 │ 预警与规则 │ 情景推演        │
│ 报告中心 │ 数据源/质量/导入 │ 用户/角色/基础数据/审计/调度 │ 系统监控 │ 数据大屏 │ 通知中心   │
└───────────────────────────────────────┬─────────────────────────────────────────────────────┘
                                        │ HTTP / JSON（axios，Bearer JWT 或 X-Api-Key）
┌───────────────────────────────────────▼─────────────────────────────────────────────────────┐
│ 接入层：请求 ID、访问日志、指标采样、CORS、异常统一处理、SPA 静态回退                        │
├─────────────────────────────────────────────────────────────────────────────────────────────┤
│ 应用层（FastAPI，14 个路由模块 / 15 个服务模块）                                             │
│ 认证与元数据 │ 驾驶舱聚合 │ 价格查询与统计 │ 预测与批量 │ 模型治理与实验 │ 预警与通知        │
│ 情景推演 │ 报告生成与导出 │ 数据接入与质量 │ 后台管理 │ 可观测性 │ 开放 API                   │
├─────────────────────────────────────────────────────────────────────────────────────────────┤
│ 领域服务：预测（季节分解/Holt-Winters/GBR/组合）、漂移 PSI、预警规则引擎、情景传导、报告模板 │
└───────────────────────────────────────┬─────────────────────────────────────────────────────┘
                                        │ SQLAlchemy 2 / redis-py / minio-py / smtplib
┌───────────────────────────────────────▼─────────────────────────────────────────────────────┐
│ 基础设施：MySQL 8（主存储） │ Redis 7（缓存+令牌黑名单+限流） │ MinIO（报告与模型产物）      │
│ Mailpit（邮件落件） │ 进程内调度器（cron），旁挂备份脚本与门禁脚本                          │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 3. 技术选型与理由

| 层次 | 选型 | 版本 | 选用理由 |
| --- | --- | --- | --- |
| 前端框架 | Vue 3 + TypeScript + Vite | 3.5 / 5.9 / 7 | 组件生态成熟，构建快，类型安全 |
| UI 与图表 | Element Plus + ECharts | 2.11 / 6 | 表格与图表能力覆盖监测与预测场景 |
| 状态与路由 | Pinia + Vue Router | 3 / 4.6 | 权限菜单与路由守卫实现简单 |
| 后端框架 | FastAPI + Uvicorn | 0.162 / 0.41 | 自动 OpenAPI、依赖注入便于接口级鉴权 |
| ORM | SQLAlchemy 2 | 2.1 | 模型集中定义，便于数据库设计与迁移 |
| 主数据库 | MySQL 8（InnoDB/utf8mb4） | 8.0.46 | 事务与索引能力满足汇总查询；提供 SQLite 回退 |
| 缓存 | Redis 7 | 7.4.12 | 驾驶舱与字典热点缓存、令牌黑名单、开放 API 限流 |
| 对象存储 | MinIO（S3 协议） | 社区版 | 报告与模型产物统一对象键，支持本地 FS 降级 |
| 预测算法 | numpy/pandas/statsmodels/scikit-learn | — | 季节分解、指数平滑、梯度提升可在单机秒级完成 |
| 邮件 | smtplib + Mailpit | — | 内网无邮件服务器时可在 Web 收件箱核验 |
| 调度 | 进程内 cron 线程 | — | 5 个任务规模无需外部调度系统，重启可续跑 |
| 测试 | Playwright + Node 脚本 | 1.65 | 接口、端到端、截图、数据库校验统一在同一套脚本内 |

技术取舍的完整记录见 `DECISIONS.md`（D01～D27），关键取舍：不引入 Kafka/Airflow/MLflow/ELK/Prometheus/K8s，改用 Redis Streams 预留、进程内调度、`model_run` 实验记录、JSONL 日志与内存指标替代，降低部署复杂度并保持能力可验证。

## 5. 关键流程设计

### 5.1 认证与鉴权

登录 → 校验 PBKDF2 口令 → 签发 HS256 JWT（含 `jti`，有效期 720 分钟）→ 前端存 `ap_token` 并写入权限列表 → 后续请求携带 `Authorization: Bearer`。后端 `get_current_user` 校验签名、过期与 Redis 黑名单；接口用 `require_permission` 声明权限点；前端路由守卫与菜单按权限过滤形成双重控制。注销时把令牌摘要写入 Redis 黑名单，剩余有效期即失效。

### 5.2 预测与回测

读取价格与特征 → 按品种×地区构造日序列（1,411 天）→ 分别训练季节分解、Holt-Winters、梯度提升回归 → 以 holdout 区间滚动回测得 MAPE/RMSE/方向准确率 → 按误差倒数加权为组合模型 → 生成 7/14/30 天点值与置信区间 → 输出方向、置信度、因素贡献与结论摘要。方向准确率主口径为 30 日趋势累计命中率（先做 7 日中心移动平均去噪，比较未来 30 天累计涨跌幅符号，|累计|<0.15% 记震荡不计入分母）。

### 5.3 批量预测（异步）

提交任务后写批次记录并立即返回"排队中/进度 0"，后台守护线程按组合逐条预测，更新 `done/progress`，失败组合记录错误；前端每 1.5 秒轮询直至完成，支持结果导出。

### 5.4 预警闭环

规则（阈值/波动率/同比/价差）× 窗口 → 扫描近 N 天数据 → 命中生成预警（分级）→ 广播站内通知、按等级发邮件 → 处置人确认（处理中）或关闭（已关闭）→ 处置时长进入 SLA 统计。

### 5.5 情景推演

选择模板或自定义冲击 → 产量与运费、政策、替代品冲击按传导系数叠加 → 生成价格变动幅度、区间、风险等级与建议 → 落库并可在历史中回看。

### 5.6 数据导入与质量

上传 CSV → 逐行校验（品种/地区存在性、日期格式、价格区间、最低价≤均价≤最高价、成交量非负）→ 正常行入库、重复行跳过计数、非法行写入质量问题 → 刷新数据源记录数 → 计算质量指标（完整率/重复率/异常波动/缺失估算）→ 触发缓存失效与导入完成通知。

### 5.7 调度与可观测性

进程内调度器每 30 秒检查 5 个 cron 任务，到期则在会话内执行并写运行史（状态、耗时、结果、错误），失败重试一次；所有请求经中间件生成请求 ID、记录访问日志与指标（含缓存命中），系统监控页提供指标时序、日志检索与服务状态。

## 6. 数据视图

- 主数据：品种、地区、市场、数据源。
- 事实数据：价格记录（唯一约束：品种+市场+日期+市场类型）、特征记录。
- 模型与预测：模型版本、模型实验、预测结果、预测批次与明细、回测记录。
- 业务数据：预警规则与预警、情景、报告、导入任务、质量问题、通知、邮件日志。
- 治理数据：用户、角色、权限、菜单、审计、调度任务与运行史、开放 API 调用方与流水。

表结构与字段含义详见 `03-数据库设计.md`；每张表的行数基线见 `00-交付物清单.md`。

## 7. 部署视图

| 组件 | 端口 | 部署方式 | 降级策略 |
| --- | --- | --- | --- |
| 前端 | 5177（开发）/ 8017 静态托管（验收） | Vite 开发服务器或后端托管 `frontend/dist` | 构建产物缺失时仅影响界面访问 |
| 后端 | 8017 | Uvicorn 单进程 | — |

| Redis | 16379 | Docker 容器 | 缓存与黑名单降级为内存，接口仍可用 |
| MinIO | 9000/9001 | 容器或本地二进制 | 自动降级为本地文件存储 |
| Mailpit | 1025/8025 | Docker 容器 | 邮件记录标为失败，站内通知不受影响 |

## 8. 质量属性设计

| 属性 | 设计措施 |
| --- | --- |
| 性能 | 汇总查询走索引与 30～300 秒热点缓存；批量预测异步化；列表分页上限 200 |
| 可靠性 | Redis/MinIO/邮件全部"失败降级"，不影响主流程；异常统一转换为业务错误码 |
| 安全性 | 口令 PBKDF2、接口级权限、令牌黑名单、开放 API 密钥与限流、全量写操作审计 |
| 可观测性 | 请求 ID、结构化日志、分钟指标、任务运行史、服务健康四态 |
| 可维护性 | 模型集中定义、契约文档冻结、种子可重放、五道门禁脚本化 |
| 可移植性 | MySQL/SQLite 双后端；对象存储 S3/FS 双后端；容器与二进制两种基础设施获取方式 |
