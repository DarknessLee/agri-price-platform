# 接口契约（M2 增强阶段增量）

本文件是 `docs/接口契约.md` 的增量补充，仅覆盖 M2 增强能力；既有端点与返回结构保持不变。
统一响应、分页、错误码、鉴权（`Authorization: Bearer <token>`）均沿用既有契约。

## 0. 数据模型增量（已由 Lead 落库）

| 表 | 字段 | 说明 |
|---|---|---|
| `sys_notification` | id, user_id, username, title, content, category, level, link, read_at, created_at | 站内通知；`user_id=0` 表示全员可见 |
| `open_api_client` | id, name, client_key, secret, enabled, rate_limit, call_count, last_call_at, description, created_at | 开放 API 调用方与限流配置 |
| `open_api_call` | id, client_id, path, method, status, elapsed_ms, created_at | 调用流水，保留 7 天用于统计 |

配置常量（`backend/app/config.py`）：
`OPEN_API_RATE_LIMIT=60`、`OPEN_API_CALL_RETENTION_DAYS=7`、`DRIFT_BINS=10`、
`DRIFT_PSI_WATCH=0.1`、`DRIFT_PSI_DRIFT=0.25`、`DRIFT_WINDOW_DAYS=90`、`DRIFT_BASELINE_DAYS=180`、
`ALERT_SLA_HOURS=24`、`NOTIFICATION_RETENTION_DAYS=90`。

## 1. 模型治理

### GET /api/models/drift?window=90
权限：`forecast:view`

```json
{
  "items": [
    {
      "model_id": 118, "key": "ensemble-pig-110000", "name": "组合模型·生猪·北京",
      "algorithm": "ensemble", "variety": "生猪", "region": "北京",
      "status": "在用", "mape": 1.73, "recent_mape": 1.92,
      "psi": 0.062, "drift_level": "平稳",
      "mape_change": 0.19, "trained_at": "2026-11-12T15:04:28",
      "last_checked_at": "2026-11-12T18:20:00"
    }
  ],
  "summary": {"total": 30, "stable": 4, "watch": 18, "drifted": 8, "avg_psi": 0.2565},
  "window": 90,
  "checked_at": "2026-11-12T18:20:00"
}
```

口径：PSI 基于日收益率分布（按日聚合批发均价后计算逐日涨跌幅），当前窗口为最近 90 天，
基线窗口为当前窗口之前的 180 天，分箱按基线 10 分位数切分；样本不足 20 条时退化为
`feature_record.volatility_30d` 分布。`psi < 0.1` 平稳、`0.1 ~ 0.25` 关注、`> 0.25` 漂移。
窗口取 90/180 天而非 30/90 天：价格日收益率噪声大，30 天窗口下每箱样本过少会把随机波动误判为漂移。
`window` 查询参数可在 30~365 天间调整（前端提供 30/60/90），当前窗口随之变化，基线窗口取 `max(window, 180)` 天。
`recent_mape` 为最近 30 天回测 MAPE；`mape_change` = recent_mape - mape。

### GET /api/models/compare?variety_id=&region_id=（已存在，前端使用）
返回同一品种/地区下各算法对比行：`[{key,name,algorithm,mape,rmse,direction_acc,is_active,trained_at}]`。

## 2. 批量预测异步化

`POST /api/forecast/batch` 保持请求/响应结构，但改为**后台线程执行**，立即返回：

```json
{"batch_id": 7, "total": 30, "status": "排队中", "progress": 0, "created_at": "..."}
```

`GET /api/forecast/batch/{id}` 增加字段：`progress`（0~100 整数）、`status ∈ 排队中/执行中/已完成/部分失败/失败`，
`items` 在完成前可为已完成部分。前端沿用 1.5s 轮询。

## 3. 报告 Excel 导出

### GET /api/reports/{id}/download?format=xlsx
权限：`report:view`。返回 `.xlsx`（`openpyxl` 生成），Content-Type
`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。

工作表：`概览`（标题/类型/周期/生成人/生成时间/关键指标）、`价格与预测`（品种、地区、指标、数值）、
`预警摘要`（级别、数量、占比）。格式非法返回 E4001。

### GET /api/reports/template?report_type=daily|weekly|monthly
权限：`report:view`。返回空白模板 `xlsx`，含表头与示例行说明。

## 4. 站内通知

### GET /api/notifications?unread_only=false&category=&page=1&page_size=20
登录即可（返回当前用户 `user_id` 或全员的 `user_id=0` 通知）。

```json
{"list":[{"id":1,"title":"生猪价格低位预警","content":"…","category":"预警",
  "level":"高","link":"/alert/list","is_read":false,"created_at":"2026-11-12T17:36:00"}],
 "total": 8, "unread": 5, "page": 1, "page_size": 20}
```

### GET /api/notifications/summary
`{"unread": 5, "by_category": [{"category":"预警","count":3}]}`

### POST /api/notifications/{id}/read
`{"id": 1, "is_read": true}`；不存在返回 E4040。

### POST /api/notifications/read-all
`{"updated": 5}`（仅更新当前用户可见的未读通知）。

通知产生链路（写库，不做外部推送）：
- 预警扫描产生新预警 → 通知 `user_id=0`，category=预警，level 取预警级别，link=/alert/list
- 预警 ack/close → 通知处置人 `user_id`，category=预警
- 数据导入完成 → 通知发起人，category=数据，link=/data/import
- 报告生成完成 → 通知生成人，category=报告，link=/report
- 模型训练/重训完成 → 通知触发人，category=模型，link=/forecast/models
- 调度任务执行 → 通知 admin，category=任务，link=/admin/tasks

## 5. 预警处置时效（SLA）

### GET /api/alerts/sla?days=30
权限：`alert:view`

```json
{"avg_handle_hours": 6.4, "within_sla_rate": 82.4, "sla_hours": 24,
 "handled_total": 12, "overdue_open": 2, "open_total": 6,
 "by_level": [{"level":"高","count":3,"avg_handle_hours":2.1,"within_sla_rate":100.0}],
 "by_area": [{"region":"北京","count":2,"avg_handle_hours":5.0}],
 "trend": [{"date":"2026-11-12","handled":2,"avg_handle_hours":4.5}]}
```

口径：`handled_at - created_at` 小时数；`within_sla_rate` 为 ≤ `ALERT_SLA_HOURS` 的比例；
`overdue_open` 为未关闭且已超过 SLA 的预警数。

## 6. 开放 API 治理

### 鉴权与限流（/api/open/v1/*）
1. `Authorization: Bearer <JWT>`（既有方式）或 `X-Api-Key: <client_key>`（新增）。
2. `X-Api-Key` 无效/停用 → 401 `E4010`；按调用方 `rate_limit`（次/分钟）计数，超限 → 429 `E4290`
   「调用频率超出限制，请稍后重试」。
3. 每次调用写 `open_api_call`（path/method/status/elapsed_ms），并累计 `open_api_client.call_count`、
   `last_call_at`；流水超过 7 天自动清理（在写入时顺带删除，避免额外定时任务）。

### GET /api/open-clients
权限：`admin:base`。`[{id,name,client_key,secret_masked,enabled,rate_limit,call_count,last_call_at,created_at,description}]`
（secret 仅显示前 6 位 + `****`）。

### POST /api/open-clients
权限：`admin:base`。请求 `{name, rate_limit=60, description}`；响应**仅此一次**返回明文
`{"id":4,"name":"…","client_key":"ak_…","secret":"sk_…","enabled":true,"rate_limit":60}`。

### PUT /api/open-clients/{id}
权限：`admin:base`。请求 `{enabled?, rate_limit?, description?}`；返回更新后的行（掩码 secret）。

### POST /api/open-clients/{id}/rotate
权限：`admin:base`。轮换密钥，返回新的 `client_key` 与明文 `secret`（仅此一次）。

### DELETE /api/open-clients/{id}
权限：`admin:base`；删除调用方与其流水。返回 `{"id":4,"deleted":true}`。

### GET /api/open-clients/{id}/usage?days=7
权限：`data:view`。

```json
{"client_id":1,"days":[{"date":"2026-11-12","count":42}],
 "total": 240, "avg_elapsed_ms": 23, "error_rate": 1.25,
 "top_paths":[{"path":"/api/open/v1/prices","count":120}],
 "last_call_at":"2026-11-12T18:02:11"}
```
