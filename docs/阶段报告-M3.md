# 阶段报告 · M3（基础设施等价落地）

- 阶段：M3 · 基础设施增强（调度运行史、对象存储、可观测性、实验跟踪与备份）
- 日期：2026-11-13
- 结论：四类基础设施能力全部落地并通过五道门禁（构建 / 数据库 / 接口 / 端到端 / 文档）

## 1. 目标

对照方案中未引入的重型组件（Kafka、Airflow、MinIO、MLflow、ELK、Prometheus + Grafana、K8s、TimescaleDB），在不降低业务完整度的前提下补齐对应能力：

| 原方案组件 | 本阶段实现方式 | 落地形态 |
| --- | --- | --- |
| MinIO 对象存储 | MinIO 服务端（S3 协议） | `agri-minio`：容器镜像或被镜像站拒绝时回退官方服务端二进制，9000/9001 |
| Airflow 调度 | 进程内 cron 调度器 + 任务运行史 | `backend/app/scheduler.py`、`scheduled_task_run` 表、`/api/tasks/tick` |
| MLflow 实验跟踪 | 训练实验表 + 实验对比界面 | `model_run` 表、`/api/models/runs`、`/api/models/retrain-drifted` |
| ELK 日志检索 | JSON Lines 结构化日志 + 检索接口 | `backend/app/logging_setup.py`、`/api/logs` |
| Prometheus + Grafana | 进程内分钟指标 + 监控页 | `backend/app/services/metrics.py`、`/api/metrics/*`、系统监控页 |
| 邮件 / 短信通知 | SMTP + 本地收件箱（Mailpit） | `agri-mailpit` 容器、`sys_email_log` 表、`/api/mail/test` |
| Kafka 事件总线 | 同步通知 + 后台线程（保持既有实现） | 暂缓，见第 6 节 |
| K8s 编排 | Docker Compose + 本地脚本 | `deploy/docker-compose.yml`、`scripts/infra.mjs` |
| TimescaleDB | MySQL 8 + Redis 缓存 | 数据量级（8.4 万价格点）无需时序扩展，见 D12 |

## 2. 范围

### 2.1 本阶段实现

- 调度：5 条定时任务具备 cron 解析、到点触发、执行留痕（成功/失败/耗时/触发方式）、失败自动重试一次并推送站内通知与邮件。
- 任务运行史：单任务与全局运行史分页查询，任务列表展示 cron 表达式中文含义、下次执行时间、累计运行次数。
- 对象存储：报告正文、模型产物、导入原始文件统一走对象键（`reports/report_{id}_{type}.html`、`models/...json`、`imports/...`），支持 MinIO 与本地 FS 双后端自动降级。
- 可观测性：结构化请求日志（request_id、耗时、状态、缓存命中）、分钟级指标（QPS、P50/P95/P99、错误率、缓存命中率、慢请求 Top）、服务状态聚合（数据库/缓存/存储/调度/邮件/日志/指标/运行时长）。
- 邮件通道：站内通知按等级规则外发邮件（预警高等级、报告、模型非高等级、任务高等级或失败），发送结果入库 `sys_email_log`，可在系统监控页一键测试。
- 实验跟踪：每次训练写入 4 条算法实验记录（超参、指标、样本量、耗时、产物键），支持按品种/地区筛选与详情查看；支持按漂移程度一键重训。
- 备份：`backup` 脚本导出 MySQL 结构与数据、对象存储清单，产物落 `.runtime/backups/`。

### 2.2 本阶段不做（保持暂缓）

- Kafka 事件总线、MinIO 之外的分布式存储、Prometheus 服务器与 Grafana 面板、K8s 编排、TimescaleDB 连续聚合、ELK 集群、短信网关。

## 6. 已知限制

1. Kafka、Prometheus/Grafana、K8s、TimescaleDB、ELK 仍为暂缓项：事件链路为同步通知 + 后台线程，指标仅在进程内存中聚合（重启归零），日志检索基于本地文件尾部扫描。
2. MinIO 镜像在本机可访问的镜像站被拒绝（`error from registry: denied`），当前运行 MinIO 官方服务端二进制（同一 S3 协议、同一端口与凭据）；`deploy/docker-compose.yml` 保留了服务定义，在可拉取镜像的环境直接 `docker compose up -d agri-minio` 即可切换。
3. 邮件通道为本地 Mailpit 收件箱，未接真实 SMTP 服务商；短信未接入。
4. 调度器为单实例进程内线程，多实例部署会重复触发；生产化需引入分布式锁或外部调度。
5. 备份为脚本级（结构与数据导出 + 对象清单），未实现自动恢复演练与异地容灾。
6. 任务运行史与日志保留 30 天，超出部分由清理逻辑滚动删除。

## 7. 后续计划

1. 事件总线：引入 Redis Streams 承载批量预测与通知，支持重试与死信队列（不引入 Kafka）。
2. 监控持久化：指标写入 MySQL 分钟表并保留 7 天，配合慢查询与告警阈值规则。
3. 调度高可用：数据库租约锁 + 多实例抢占，避免重复执行。
4. 对象存储生产化：MinIO 镜像可达环境直接启用容器，增加生命周期与版本化策略。
5. 备份恢复演练：每月一次从 `.runtime/backups/` 恢复到临时库并校验行数与指标。
