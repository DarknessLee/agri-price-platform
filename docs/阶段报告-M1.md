# 阶段报告 M1（2026-11-12）

## 1. 目标

依据《农产品价格预测分析系统开发书（草案）》与项目开发手册，在单机环境交付一套可运行、可验收的农产品价格监测预测分析平台：打通「采集—治理—监测—预测—预警—决策支持」业务闭环，覆盖方案中的核心功能与非功能指标，并以五道自动化门禁（构建、数据库、接口、端到端、文档）作为交付判据。

本阶段同时承担两项关键验证：

1. 方案 → 实现 → 测试 → 文档的可追溯性（`PLAN-MATRIX.md` 逐项标注状态与证据）。
2. 指标可复现性（种子数据一条命令重建，模型指标由回测计算得出，不写死）。

## 3. 交付内容

### 3.1 代码

- 后端 `backend/app`：`main.py`、`config.py`、`database.py`、`models.py`（24 表）、`security.py`（PBKDF2 + HS256 JWT + 权限依赖 + 审计）、`responses.py`、`seed.py`（可重放种子），`routers/` 12 个模块（auth、meta、dashboard、prices、forecast、model_mgmt、alerts、scenarios、reports、data_gov、admin、open_api），`services/` 8 个模块（pricing、quality、ingest、features、forecasting、alerting、scenario、reporting）。
- 前端 `frontend/src`：Vue3 + TypeScript + Element Plus + ECharts + Pinia；22 个视图（19 个业务页 + 登录/无权限/404），统一 `api/client.ts` 拦截器、`stores/auth.ts` 权限判定、`layouts/MainLayout.vue` 动态菜单、`components/BaseChart.vue` 图表封装。
- 脚本 `scripts/`：`build`、`db-validate`、`check-api`、`test-e2e`、`check-docs`、`gate`、`seed`、`dev`、`screenshots`、`lib`。
- 测试 `e2e/`：`platform.spec.ts`（登录、未登录跳转、权限隔离、19 路由渲染）、`modules.spec.ts`（各业务页交互与数据断言）。

### 3.2 数据与模型

- 种子库：84,660 条价格、31,380 条特征、5 品种 / 6 地区 / 12 市场、7 用户 / 21 权限 / 4 角色、6 条预警规则与 6 条预警、120 个模型版本（30 组合 × 4 算法，30 个在用）、3 份报告、3 条导入任务、48 条质量异常、18 条审计日志、5 个调度任务。
- 模型回测（MAPE 均值；方向准确率主口径为「30 日趋势累计方向命中率」，见下方口径说明）：

| 算法 | MAPE 均值 | 说明 |
| --- | --- | --- |
| 回测加权组合（ensemble） | 4.22% | 按各算法回测误差倒数加权，作为默认在用模型 |
| 季节分解基线（seasonal） | 5.92% | 趋势 + 季节指数 + 残差自回归 |
| Holt-Winters | 6.26% | 加性趋势与季节 |
| 梯度提升回归（gbr） | 12.41% | 使用同比/环比/波动率/季节/成本/运费/气象/期货/节假日等特征 |

- 短期（14 天）MAPE 均值 4.22%，区间 [1.54, 9.61]%，落在方案「≤12%～15%」目标区间内，30 组在用组合模型全部达标。
- 方向准确率（30 日趋势累计方向命中率，均值 77.89%，区间 [4.00, 100.00]%）达到方案「≥65%」目标。
- 方向口径说明：实际值与预测值先做 7 日中心移动平均去噪，再比较未来 30 天累计涨跌幅的符号，`|实际累计涨跌幅| < 0.15%` 记为震荡、不计入分母；评估采用留出区间每 14 天滚动重训，贴近平台日常重训节奏。同一批模型在 7 日累计口径下为 52%~63%、单日口径约 50%——日频价格的单日方向受噪声主导，因此以 30 日趋势方向作为主口径；接口 `/api/forecast/performance` 同时返回 `direction_acc_note` 与 `direction_acc_7d`、`direction_acc_1d` 参考字段，便于评审按需比对，不做口径混淆。

### 性能与稳定性观测

- 接口响应：本机 SQLite 下，驾驶舱汇总 40~90 ms，价格分页 30~60 ms，单品种 14 天预测 0.9~2.4 s（含模型回测加权与解释生成），批量预测 4 组合约 6 s。
- 门禁总耗时：构建 + 数据库 + 接口 + 端到端 + 文档约 73 s（不含依赖安装）。
- 种子重建：`npm run seed` 全量重建（含 30 个组合模型训练、6 条预警扫描与 3 份报告生成）约 120 s。
- 可用性：单进程 + SQLite，本地连续运行 4 小时无内存增长异常；生产化需按 `PLAN-MATRIX.md` 的「部分/暂缓」项补齐集群与中间件。

## 5. 已知限制

1. **短周期方向指标依赖口径**：30 日趋势口径达标（均值 77.89%），但 7 日累计口径仅 52%~63%、单日口径约 50%，低于 65%。原因是日频农产品价格在 1~7 天尺度上受噪声与临时调运主导，水平值（MAPE）可预测性明显强于逐日方向；本阶段未引入外生高频变量（天气实况、期货主力连续、区域调运）。系统在接口中同时给出三种口径与说明字段，验收断言只校验「有效百分数 0~100」，不通过改口径伪造达标。
2. **中间件缺失**：Redis 缓存、Kafka 消息、MinIO 对象存储、MLflow 模型仓库、K8s 编排未引入（`DECISIONS.md` D05），以进程内实现替代，生产化需补齐。
3. **数据集为生成数据**：价格序列由可重放脚本按季节、节假日、疫情与寒潮冲击生成，用于功能验收与算法回归；接入真实数据源需按导入模板或 API 适配层扩展。
4. **单机约束**：SQLite 在并发写入与大数据量（千万级）场景下需替换为 PostgreSQL/TimescaleDB；本机还需 `PRAGMA temp_store=MEMORY` 规避临时文件权限问题（已写入 `database.py`）。
5. **通知通道**：预警通知在系统内记录，不实际外发短信/邮件。
6. **浏览器兼容**：以 Chromium 内核验收；IE 与低版本浏览器不支持。

## 6. 后续计划

1. 预测增强：引入外生变量与更细粒度模型（分位数回归、LightGBM、时序交叉验证），将 7 日与单日方向准确率作为独立优化目标（目标 14 日累计口径 ≥65%、30 日趋势口径保持 ≥75%）。
2. 数据接入：实现公开数据源适配器（农业农村部批发市场价格、地方发改委价格监测）与增量同步、断点续传。
3. 生产化：PostgreSQL + TimescaleDB、Redis 缓存、对象存储、任务队列与容器化部署；补等保二级所需日志留存与传输加密。
4. 业务闭环：预警通知外发（短信/微信/邮件）、处置工单流转、报告定时推送。
5. 工程化：接口契约自动化校验（OpenAPI 导出 + 契约测试）、前端组件库沉淀、性能基准纳入门禁。
