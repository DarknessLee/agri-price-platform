# 接口契约（M3 增量）

> 本文件是 M3 增强阶段的增量契约，与 `docs/接口契约.md`（M1）、`docs/接口契约-M2.md`（M2）叠加生效。
> 统一响应仍为 `{code,message,data}`；分页仍为 `{list,total,page,page_size}`；鉴权仍用 Bearer JWT。

## 0. 新增数据表与配置

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `scheduled_task_run` | 调度任务运行史 | id, task_id, task_key, task_name, trigger（定时/手动）, status（成功/失败）, result, error, duration_ms, started_at, finished_at |
| `model_run` | 模型训练实验记录 | id, model_id, key, name, algorithm, variety_id, region_id, version, trigger, status, params, metrics, rows, duration_ms, artifact_key, operator, created_at |
| `sys_email_log` | 邮件通道发送记录 | id, to_addr, subject, category, status（已发送/失败）, reason, created_at |

新增配置（均可 env 覆盖）：`STORAGE_BACKEND=minio`（`AGRI_STORAGE=fs` 回退本地目录）、`STORAGE_BUCKET=agri-artifacts`、`MINIO_ENDPOINT=127.0.0.1:9000`、`SCHEDULER_ENABLED=true`、`SCHEDULER_TICK_SECONDS=30`、`MAIL_HOST=127.0.0.1`、`MAIL_PORT=1025`、`MAIL_ALERT_LEVELS=高`、`LOG_FILE=.runtime/logs/app.jsonl`、`METRICS_WINDOW_MINUTES=60`、`BACKUP_DIR=.runtime/backups`。

## 1. 调度任务（权限 `admin:task`）

`GET /api/tasks` → 数组，每项在原字段上增加 `cron_text`（中文描述）与 `runs`（累计运行次数）。

`POST /api/tasks/{id}/run` → `{ok,status,result,duration_ms,run_id,next_run_at}`；执行真实动作（同步价格、扫描预警、重训漂移模型、生成日报、质量巡检），写运行史并广播通知。

`GET /api/tasks/runs?status=&key=&page=&page_size=` → 分页运行史，按开始时间倒序；行字段 `{id,task_id,task_key,task_name,trigger,status,result,error,duration_ms,started_at,finished_at}`。

`GET /api/tasks/{id}/runs?page=&page_size=` → 单任务运行史分页。

`POST /api/tasks/tick` → `{checked,due,triggered,failed,details:[{task,status,result}]}`，立即执行到期任务（等价调度器一次心跳）。

调度语义：cron 五段（分 时 日 月 周，周 0=周日），支持 `*`、`*/n`、`a-b`、`a,b`；日与周同时限定时取「或」；服务重启后按库中 `next_run_at` 续跑。

## 2. 可观测性

`GET /api/logs?limit=100&level=&module=&keyword=`（权限 `admin:audit`）→ `{list:[{ts,level,event,request_id,method,path,status,elapsed_ms,cache}],stats:{path,files,total_bytes,max_bytes,backup_count}}`；`limit` 上限 500。

`GET /api/metrics/summary?minutes=60`（权限 `admin:task`）→
`{window_minutes,qps,avg_ms,p50_ms,p95_ms,p99_ms,error_rate,total,errors,cache:{HIT,MISS,BYPASS,hit_rate},slow_top:[{path,count,avg_ms,error_rate}],slowest:[{method,path,status,elapsed_ms,at}],updated_at}`。

`GET /api/metrics/timeseries?minutes=60` → `[{minute,qps,avg_ms,error_rate,total}]`，分钟级补零。

`GET /api/system/status`（登录即可）→ `{db,cache,storage:{configured,backend,ok,bucket,endpoint,degraded,error},scheduler:{enabled,running,tick_seconds,last_tick_at,last_result},mail:{enabled,endpoint,web_ui},logs:{path,files,total_bytes},metrics:{window_minutes,total},uptime_seconds,checked_at}`。

## 3. 邮件通道（权限 `admin:task`）

`GET /api/mail/logs?limit=20&status=` → `{list:[{id,to_addr,subject,category,status,reason,created_at}],total,sent,failed}`。

`POST /api/mail/test` `{to?}` → `{sent,to,subject,status,note}`；SMTP 不可达时 `sent=false` 且写入 `sys_email_log` 失败原因，不抛 500。

通知联动：高等级预警、任务失败、报告生成、模型重训成功后按 `MAIL_ALERT_LEVELS` 发送邮件，成功/失败均落 `sys_email_log`。

## 4. 模型实验与重训（权限 `model:manage` 写，`forecast:view` 读）

`GET /api/models/runs?variety_id=&region_id=&limit=50` → `{list:[{id,model_id,key,name,algorithm,variety,region,version,trigger,status,params,metrics:{mape,rmse,direction_acc,rows},rows,duration_ms,artifact_key,operator,created_at}],total}`。

`POST /api/models/retrain-drifted` `{limit=5,window=90}` → `{trained,failed,items:[{variety,region,psi,mape,status}]}`；仅重训漂移等级为「漂移」的组合，最多 `limit` 组。

训练产物：每次 `train_model` 写入 `model_run` 并调用 `storage.put_bytes(model_key(...))` 归档参数与指标 JSON。

## 5. 对象存储

`GET /api/storage/health`（权限 `admin:task`）→ `{configured,backend,ok,bucket,endpoint,degraded,error}`。

报告与模型产物统一走对象键：报告 `reports/report_{id}_{type}.html`、导入原件 `imports/{task_id}_{filename}`、模型产物 `models/{variety_id}_{region_id}_{algorithm}_{version}.json`。MinIO 不可用时自动写 `.runtime/storage/` 同键路径，下载接口对业务无差异。

`GET /api/reports/{id}/download?format=html|md|xlsx` 改为从存储读取（xlsx 见 M2 契约）。

## 6. 健康检查扩展

`GET /api/health` 增加字段：`storage`（ok/degraded）、`storage_backend`（minio/fs）、`scheduler`（ok/paused）、`mail`（ok/paused）。

`GET /api/system/info` 增加 `storage`、`scheduler`、`mail` 三个对象，`db` 文案按实际后端输出（MySQL 8 显示连接库名）。
